# Internationalization (i18n)

The UI ships in **five languages by default**:

| Code | Language |
| --- | --- |
| `en` | English (fallback) |
| `ms` | Malay (Bahasa Melayu) |
| `zh` | Mandarin Chinese (简体中文) |
| `ja` | Japanese (日本語) |
| `vi` | Vietnamese (Tiếng Việt) |

## 1. i18n ≠ localization (different axes — keep them separate)

This is the most important distinction:

| | i18n (this doc) | L10n ([LOCALIZATION.md](LOCALIZATION.md)) |
| --- | --- | --- |
| What | UI display **language** | Country **tax / currency / statutory** rules |
| Scope | **user / session** preference | **company (`company_fn`)** attribute |
| Example | A user reads the UI in Mandarin | The SG company charges 9% GST |

A user whose UI language is **Mandarin** can operate the **Singapore (GST)** company. The
two never mix:

- **Language** is stored on the user (`app_user.language`) and chosen in-session.
- **Country/currency/tax** is stored on the company and never derived from language.

> ⚠️ Do **not** hang language off `company_fn`. They are orthogonal.

## 2. Resolution & fallback

```
active language = session override
              → user.language
              → browser Accept-Language (if among the 5)
              → en  (final fallback)
```

Any missing translation key falls back to `en`, never shows a blank or a raw key.

## 3. Performance — lazy-load locale packs

Load **only the active locale**, not all five, or the bundle is ~5× larger.

```
src/i18n/
  en.json   ms.json   zh.json   ja.json   vi.json
```

- Locale packs are code-split and fetched on demand when the user switches.
- The fallback (`en`) may be bundled; the rest load lazily.

None of the five languages are right-to-left, so **no bidirectional/RTL work** is needed.

## 4. What gets translated

- All UI strings (labels, buttons, menus, validation messages).
- Date / number / currency **formatting** uses the locale (`Intl` API), but the
  **currency itself** comes from the company, not the language (a Mandarin user still sees
  SGD for the SG company).
- Document templates (invoices, POs) may be localized separately per company's customer
  base — tracked later.

## 5. Translation source of truth

- `en.json` is the canonical key set; other locales mirror its keys.
- A CI check flags keys present in `en.json` but missing elsewhere (prevents silent
  fallback drift).
- Keys are namespaced by module (`inventory.product.name`) so modules stay self-contained.

## 6. Demo

The public demo exposes the language switcher with all five locales so visitors can see
i18n working — independent of which demo company (SG/MY) they view.
