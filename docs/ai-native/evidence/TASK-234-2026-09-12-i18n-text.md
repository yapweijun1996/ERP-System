## Defect and change

`i18nInterpolate()` already HTML-escapes parameter values before returning a
localized string. Several UI templates wrapped those parameterized results in a
second `esc()` call, so a module label such as `Expenses & Tax` reached the DOM
as `Expenses &amp; Tax`. The focused repair removes only the redundant outer
escape for parameterized text nodes and keeps ordinary static text and
attribute/value escaping unchanged. The existing module access title fix is
covered for all five supported locales; the route access body also exercises a
company name containing `&`.

Expected: localized titles and messages display their translated characters,
including ampersands, while dynamic parameters remain HTML-safe.

Actual: Company Receipts E2E rendered the disabled-module title exactly as
follows, with no `&amp;` text:

| Locale | Rendered title |
| --- | --- |
| en | `Expenses & Tax unavailable` |
| ms | `Perbelanjaan & Cukai tidak tersedia` |
| vi | `Chi phí & Thuế không khả dụng` |
| ja | `経費と税務 は利用できません` |
| zh | `费用与税务 不可用` |

The same run rendered a permission message containing `Acme & Sons` without a
double-escaped entity.
