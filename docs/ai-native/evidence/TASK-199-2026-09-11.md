### Root cause and implementation

`check:availability` emitted a sanitized event but did not provide a canonical
command for a scheduler to pass that event through the existing default-deny
delivery adapter. `scripts/check-availability-alert.mjs` now reuses the same argument
parser, verifier, fixed-message event builder and allowlisted delivery function. It
reads an endpoint, comma-separated host allowlist, optional authorization and bounded
timeout from environment variables; no endpoint means an explicit dry-run. The new
`check:availability-alert` package command returns exit `1` for degraded release
evidence and exit `2` for delivery configuration/sink failure on an otherwise healthy
release. No new alert destination or responder is selected by source code.

### Actual result

- Healthy and degraded verifier results produce bounded recovered/degraded events in
  dry-run mode without attempting a sink request.
- Explicit allowlisted HTTPS configuration delivers one event with its deterministic
  `idempotency-key`; authorization is forwarded only to the injected fixture.
- Missing allowlists, rejected sink responses and timeout errors fail closed with
  stable application-owned codes and no sink response or transport detail in output.
- Invalid CLI arguments return a fixed `invalid_argument` result without echoing the
  supplied detail.
