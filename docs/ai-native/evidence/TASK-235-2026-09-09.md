## S1 — Define the semantic contract

The new [`semanticContracts.ts`](../../../src/modules/agent/semanticContracts.ts)
publishes contract version 1 for the first bounded semantic surface:

| Contract area | Source-backed rule | S1 implementation/evidence |
| --- | --- | --- |
| Entity and questions | `company_receipt`; count confirmed receipts and total confirmed receipt amounts by currency for an inclusive date range | `COMPANY_RECEIPT_SEMANTIC_CONTRACT` names the entity, source resource, supported questions and terms |
| Tenant and visibility | `masterFn` and `companyFn` come from the server session/active Company; `own` filters `uploaderUserId`, `company` retains all rows in the active Company | `CompanyReceiptSemanticQuery` carries server-derived scope and `summarizeCompanyReceipts` repeats the scope/visibility boundary as defense in depth |
| Time | `transactionDate` is date-only; `dateFrom` and `dateTo` are inclusive; null transaction dates are excluded; the Company IANA `timeZone` labels the interpretation; `asOf` is a server-observed ISO timestamp | Query validation and result metadata preserve the exact dates, timezone and as-of timestamp |
| Status | Only `ready` is a confirmed Company Receipt; `draft`, `processing`, `needs_attention` and `voided` are excluded | The contract and reducer fail closed for unknown statuses and exclude all non-ready rows |
| Amount and currency | Positive stored Decimal amounts are summed without model arithmetic or FX conversion; each currency remains a separate total | Decimal.js aggregation returns four-decimal strings and deterministic currency ordering |
| Evidence | Each included fact carries receipt ID/version, governed document ID and document-version ID | `sources` is returned at result and currency-total level and is asserted exactly in golden fixtures |

The contract deliberately does not parse a model question, construct SQL, select
tenant identifiers from caller JSON or expose the developer project KB as customer
data. The pure reducer remains the deterministic contract boundary; S2 replaces
fixture-only input with a bounded authorized database read while preserving the same
output and semantics.

## S3 — Implement scoped SOP retrieval

The new `agent_knowledge_document` table is a Company-scoped registration boundary
for a small governed corpus. It retains the corpus key, title, managed-document and
document-version IDs, effective-date window (`effectiveTo` is exclusive), required
permission, server-owned field allowlist, status/version and revocation metadata.
The content itself remains in `managed_document`, `document_version` and the
successful `document_extraction` row; the new table cannot become a second content
store. Migration 0109 adds the table and the production overlay now includes its
generic FORCE-RLS tenant policy.

`registerGovernedSopWithin` requires live `documents.governance.manage`, the active
Company session, an `other` managed document in an approved/posted/sealed/corrected
record state, the current document version, a clean scan and successful non-empty
extraction. It stores no prompt or model instructions. `searchGovernedSopWithin`
checks `documents.knowledge.read` inside the tenant transaction before the query that
selects extraction text, then filters by server-derived Company scope, active corpus
status, effective date, retention, record status, clean scan and successful
extraction. Requested fields must be in the registered allowlist; rows that cannot
provide the requested fields are omitted rather than downgraded. Results are bounded
to 20, use an ID cursor, cap content at 4,000 characters and label returned text as
`untrusted_document_data` with `instructionsExecutable: false`.

`GET /api/knowledge/sop` supplies only authenticated SessionData to the service. The
API/PGlite fixture creates an approved/extracted policy, proves content and source
metadata over the route, ignores a client `companyFn` query value, denies a viewer,
and denies an admin immediately after a live `documents.knowledge.read` permission
downgrade. Module fixtures additionally prove effective-date expiry, explicit
revocation, metadata-only field projection, content-field denial and cross-Company
non-disclosure. Embedded text containing an instruction-like sentence is returned
only as data metadata; no code path evaluates it.

## S4 — Add citations and freshness rules

S4 extends the bounded SOP result with a resolvable citation under the authenticated
`/api/knowledge/sop/:id` boundary. Each citation carries its knowledge row, managed
document/version identity when allowed, document SHA-256, effective policy dates and
the server observation time. The citation resolver repeats live permission, Company
scope, effective-date, retention, current-version, scan and extraction checks and
rejects a revoked or stale citation rather than returning a replacement source.

Policy evidence is explicitly typed as `policy` with `inference: false`. A grounded
result states that the returned content is supported by the cited governed version;
an empty current result is `unknown`; and overlapping effective sources with different
content hashes for a non-empty policy query are `conflict`. Conflict results return
bounded source citations but no policy content, so the caller cannot silently choose
one contradictory rule. Company Receipt semantic results now identify their evidence
as a grounded `transaction_fact` with `inference: false`; no AI inference is claimed.
Instruction-like text remains `untrusted_document_data` and is never executed.

The in-process retrieval cache is bounded and time-limited. A cache key includes the
authenticated actor, Master, active Company, current Company authorization version,
query, effective date, cursor, fields and bounded result size. Every request performs
the live permission check and reads the current eligible-source fingerprint before a
cache hit; source status/version/hash, extraction hash, record version, scan state or
field allowlist changes invalidate the old entry. Company switching, live permission
downgrade and source revocation therefore cannot reuse another actor or stale source's
content. No Agent memory is persisted by this retrieval layer.
