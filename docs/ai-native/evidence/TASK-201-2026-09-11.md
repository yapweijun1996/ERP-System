## Source comparison

`void Promise.resolve()`, and returns without awaiting the telemetry promise
([telemetry.ts](../../../src/worker/telemetry.ts#L350-L379)). Both worker entry points
call `emitTelemetryIfDue()` without `await` before their business processing
([worker.ts](../../../src/worker.ts#L65-L68), [calendar.ts](../../../src/worker/calendar.ts#L37-L41)).
The queue snapshot still executes whole-table aggregate reads with queue-specific
lease, attempt, connection and reminder predicates. Therefore the prior
`docs/SCALABILITY.md` statement that telemetry was awaited before business work
was stale.

`docs/SCALABILITY.md` and `docs/DESIGN.md` now state the current non-blocking
emitter behavior and queue-specific claim predicates. They retain the actual
open work: representative queue-volume plan testing, a bounded query budget,
