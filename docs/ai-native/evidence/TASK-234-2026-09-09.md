## S1 — Define runtime states and limits

`src/modules/agent/aiRuntime.ts` defines runtime contract version 1:

- Provider requests carry an explicit provider/model, run ID, typed messages and tool-call definitions. Raw provider payloads are not part of the application result contract.
- Run states are `draft`, `waiting`, `running`, `succeeded`, `failed` and `cancelled`. A successful result is returned only after the provider returns a validated response; errors never contain a simulated success response.
- `AiRuntimeLimits` makes physical provider calls, retries, whole-run duration, input characters, output characters and integer micro-USD cost explicit. Retries count against `maxProviderCalls`.
- Cost policy is `reserve_before_call_release_on_preflight_failure`; the runtime checks the per-call reservation before dispatch and enforces the returned cost before success.
- A linked cancellation signal and one whole-run deadline abort the provider call. Explicit cancellation produces `cancelled`; a deadline produces `run_timeout`.
- `createDeterministicZeroSpendProvider()` is the approved local provider/model pair (`deterministic.zero_spend` / `erp-test-zero-spend-v1`). It never uses the network and returns zero cost. `available: false` is a hard `provider_unavailable` error with `configure_provider` recovery, not a placeholder success.
- Budget, provider, output and cancellation errors use stable local codes and actionable recovery actions (`configure_provider`, `reduce_request_or_increase_budget`, `reduce_output_limit`, `retry_run` or `resume_run`). Provider error bodies are not forwarded.

Focused tests in `src/modules/agent/aiRuntime.test.ts` prove:

- deterministic zero-spend success and the complete `draft → waiting → running → succeeded` transition sequence;
- unavailable provider failure with no `response` and no `succeeded` state;
- cost reservation rejection before a provider call;
- retry attempts counted against the physical call budget;
- oversized output rejection without returning the oversized text; and
- distinct explicit cancellation and whole-run timeout outcomes.

## S2 — Implement secret-safe server configuration

`src/data/schema/agent.ts` adds the Company-owned `agent_provider_config` aggregate.
It stores provider/model, explicit data region and data policy, bounded runtime limits,
enabled/version metadata and an AES-256-GCM `credentialEnvelope`. The row is scoped by
the composite `masterFn` + `companyFn` foreign key, has one configuration per Company,
and requires the updater to be a Company member. Migration `drizzle/0110_parched_random.sql`
and the generated Demo schema include the table and constraints.

`src/modules/agent/providerConfiguration.ts` is the server-side boundary. It allowlists
the deterministic, OpenAI, Google and OpenAI-compatible provider IDs; allowlists the
implemented OpenAI/Google models; requires encrypted credentials for real providers;
supports explicit replacement or clearing; and returns only safe metadata with
`credentialConfigured`, never the envelope or tenant scope. Provider changes with an
existing credential require a new credential or an explicit clear decision. Compatible
endpoints are HTTPS-only, reject embedded credentials/query/hash/IP/localhost/local
hosts, and require an exact server egress allowlist. Runtime calls/retries, timeout,
input/output and micro-USD cost limits are bounded before persistence.

`GET /api/integration/agent-provider` derives the active Company from the authenticated
session and exposes the safe view only. The update action uses the shared command and
idempotency boundary, requires `integration.manage`, encrypts the raw secret at the
API edge, and sends only safe before/after metadata to the append-only audit log. Raw
secrets are not persisted in idempotency payloads, browser responses, public views or
audit records. Production RLS includes the new Company table and explicitly permits the
authenticated Agent issuer boundary to read its tenant row when the future execution
path needs it.

missing assistant identity, denied/invalid tool call, cancellation, stale facts,
unapproved intent or provider prose without a verified Pack fails or waits without a
